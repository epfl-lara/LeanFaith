## Objective

Build a clean continued-pretraining text corpus that adapts an encoder to Lean code, proofs, types,
and mathematical documentation. Preserve useful source text with minimal processing; training is a
later task.

## Scope and ownership

**In scope:** pinned download/streaming, schema validation, exact concatenation, exact-string
deduplication, deterministic sharding, manifests, local verification, and private Hub publication.

**Out of scope:** tokenization, MLM training, semantic filtering, goal rendering, Lean compilation,
LLM calls, fuzzy deduplication, or adding explanatory separators.

**Writable paths:** this task brief; `src/leanfaith/cpt1/`; `configs/data/cpt1/`;
`tests/unit/cpt1/`; the staging root. Existing `train2/`, shared source clients, project config,

## Output contract

Trainer configuration:

```text
text: string
```

Sidecar/manifest records source repository, pinned revision, subset/split, source row ID or stable
hash, source column recipe, raw/kept/blank/duplicate counts, shard hashes, code revision, and Hub
commit. Keep source contributions measurable without adding columns to the trainer view.

Apply only exact byte/string deduplication after validating non-null strings. Do not normalize Lean
whitespace or comments in v1. Establish a deterministic source order and shard assignment.

Screen output against `data/benchmarks/golden_blocklist_v1.json` using its frozen exact-string/hash
method without Lean. Record hits and exclude them from the default training configuration (or keep
them only in an explicitly contamination-marked diagnostic configuration).

## Lean-efficiency plan

Lean is the bottleneck; CPT1 has a zero-Lean budget. This task is pure Hugging Face, schema, string,
hash, and file work. Any proposal to compile or parse Lean is out of scope.

## Execution gates

### One-example smoke

- Fetch one `lean-docs` row and prove output text equals the input `text` exactly.
- Fetch one nonblank feedback training row and prove output bytes equal `question + answer` exactly,
  including the boundary with no inserted character.
- Serialize/read both through the chosen shard format and validate the manifest linkage.

### Pilot

Process a deterministic sample from each source, including empty/null/Unicode/long rows. Report
throughput, memory, raw/kept/duplicate counts, text-length quantiles, and a reproducibility hash.
Test interruption/resume and ensure it does not duplicate rows.

### Scale and publication

Stream or process bounded shards rather than loading the full corpus in memory. Deterministically
merge metadata, verify all shard hashes and schema/counts locally, create the private Hub dataset,
upload, then verify the remote revision and sample rows. No GPU request should be needed.

## Acceptance criteria

- Only `lean-docs.text` and feedback training `question + answer` contribute rows.
- No separator is inserted and blank-answer test rows are absent.
- Trainer-facing schema is exactly `{text}`.
- Exact deduplication and all exclusion counts are deterministic and recorded.
- Exact gold-blocklist hits are counted and absent from the default training view.
- Local and Hub counts/schema/checksums agree at a pinned commit.
- The builder is restartable and its tests require neither network nor Lean.
