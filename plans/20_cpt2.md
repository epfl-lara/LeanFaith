## Objective

Turn `formalmathatepfl/compiler_data` into a large binary proof-validity task. The model separately
encodes a theorem/context prefix and its proof body, cross-attends between them, and predicts the
existing `isValid` label. The task prepares data only.

## Input and minimal schema

Use all eligible rows from `formalmathatepfl/compiler_data`, pinned revision
`ca37d4701b11022f183e72b7b96ff543a8a615d3`. Expected scale is 4,361,579 rows with:

```text
theorem: string   # exact source prefix before the selected `by`, including terminal `:=`
body: string      # exact suffix after that `by`
label: bool       # source `isValid`, unchanged
```

The `theorem` field intentionally retains preceding imports, helper declarations/sub-statements,
and the final theorem/lemma signature. Do not convert CPT2 to `goal_v1.0`, add prompts, or relabel.
Skip unmatched rows and report aggregate reasons; no quarantine dataset, normalized-signature
grouping, global deduplication, or corpus-wide audit is required.

## Splitter theory and experiment

Implement three deterministic candidates and select by evidence:

1. **Raw reverse delimiter:** last literal `:= by` in the source.
2. **Masked reverse delimiter:** last `:= by` after masking comments, strings, and character-like
   syntax so delimiters inside text do not count.
3. **Declaration-aware scan:** locate the last top-level `theorem` or `lemma`, then its first
   top-level `:= by` boundary; tolerate attributes/modifiers and whitespace/comments.

Construct a 500-row stratified LeanInteract/declaration-range oracle across labels, lengths,
multiple declarations, nested `by`, comments/strings, and source shards. Also run a 10K-row
string-only coverage/performance sample. Choose the fastest candidate with at least 99% exact
boundary agreement and 98% eligible-row coverage. If the raw method passes, use it. Freeze the
method/version and mismatch examples before scale.

## Lean-efficiency plan

Lean is the bottleneck. All 4.36M rows use the frozen string splitter. Lean is allowed only to
create/verify the 500-row boundary oracle, using a prepared persistent project and bounded batch
workers. Cache oracle results by source hash, Lean/project revision, options, and extractor
version. Do not compile proofs merely to check source `isValid` labels.

## Execution gates

### One-example smoke

Exercise at least: a single theorem, multiple preceding declarations, and an inner proof `by`.
Show exact prefix/body round-trip (`prefix + "by" + body == source` at the chosen boundary), source
label preservation, serialized row, manifest link, and resume behavior.

### Splitter pilot

Finish the 500-row oracle and 10K cheap sample; report coverage, exact boundary rate by stratum,
rows/s, prefix/body length quantiles, failure examples, cache hits, and projected full-run wall
time. Stop if no method meets both thresholds; propose a cheap parser improvement rather than
compiling the corpus.

### Scale and publication

Process resumable deterministic shards. Screen the exact `theorem` prefix against
`data/benchmarks/golden_blocklist_v1.json` without Lean and record/exclude default-training hits.
Group rows by exact theorem-string hash so attempts for one statement never cross splits. Select
whole groups for a deterministic, approximately label-balanced 10K validation split and keep the
remaining groups for training. Validate schema/labels/round-trips and shard hashes, publish
privately, and verify the Hub revision.

## Acceptance criteria

- Splitter choice meets ≥99% exact boundary agreement and ≥98% coverage on the frozen audits.
- No more than 500 rows require Lean for splitter selection; scale extraction uses no Lean.
- Output has only `theorem`, `body`, and `label`, with unchanged source labels.
- Unmatched/skip counts are aggregated and reproducible without over-engineered quarantine/grouping.
- 10K validation selection is deterministic, group-disjoint by theorem hash, and as label balanced
  as whole groups allow; prefix-length statistics and gold-screen hits are recorded.
- Local and Hub schema/counts/hashes agree, and the job resumes without duplicate rows.
